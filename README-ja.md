# ソース定期表示 — Ambient Source Events

OBS Studioの映像ソースを一定間隔、またはランダムな間隔で表示するLua映像フィルタです。開始・終了にはそれぞれ「なし」「フェード」「Peek」「Wipe」「Zoom」を指定できます。完全非表示中は、そのソースのOBS音声をミュートします。

バージョン: **0.6.1（初版＋Peek・Wipe・Softness・Zoom＋イージング基本機能）**
基準環境: **macOS / OBS Studio 32.0.4 / SDR**
実際の検証状況は [受入試験記録](verification/ACCEPTANCE.md) を参照してください。

**初版とPeek・Wipe・Zoom・イージング基本機能の受入確認は完了しています。** Wipe Softnessはガード付きunit・実GPU統合・live reload試験に合格し、実OBSでの目視確認は未実施です。

現行コードの短時間統合試験は376項目、unit試験は3,542項目、初版に対する3分試験は82項目がネイティブ終了まで合格しました。

live reloadは、実OBSの`obs_script_reload`で再生中・待機中から各1回、計2回を終了まで確認しました。初回待機のリセット、元のミュート状態の復元、phase2の11項目も合格しています。OBSネイティブUI、Browser Source、Capture系ソース、フィルタ有効状態でのOBS本体終了も実OBS上で合格しています。

3分間の連続試験では、82実OBS項目、消音1508ブロック（ピーク0）、表示5229ブロック（最大ピーク0.13057221472263336）、正常終了、Luaエラーなしを確認しました。この結果は3分間の検証範囲を示すもので、長時間運転を保証するものではありません。

## 導入

1. `ambient-source-events.lua`を移動せず使える場所へ置きます。
2. OBSの「ツール → スクリプト → ＋」でLuaファイルを追加します。
3. 対象ソースの「フィルタ」を開き、映像のエフェクトフィルタの「＋ → ソース定期表示」を選びます。
4. タイミングとエフェクトを設定します。Media Sourceの場合は、下記の利用条件も確認します。

追加のOBSプラグイン、Python、外部シェーダーファイルは不要です。`tests/`は開発用で、利用者がOBSへ登録する必要はありません。スクリプトのパスや内部フィルタIDを変更すると、OBSの保存済み設定から読み込めなくなる場合があります。

## 対応ソース

| 分類 | 対象 | イベントの終了 |
|---|---|---|
| Media型 | OBS標準のMedia Sourceに読み込んだローカル動画・GIF | 実際のメディア再生終了 |
| Persistent型 | PNG/JPEG、Image SourceのGIF、Text、Browser、Capture等 | フィルタに設定した表示時間 |

VLC、ネットワーク配信等は初版のMedia制御の保証対象外です。それらへ適用した場合はPersistent型として表示だけを制御し、再生の先頭復帰や終了検知は行いません。

Image SourceのGIF、Browser内のアニメーション、Capture映像そのものの進行は停止しません。GIFをイベントごとに先頭から再生したい場合は、標準Media Sourceから読み込んでください。

同じソースに本フィルタを複数追加することはできません。同じソースを複数シーンで参照している場合は、すべての参照先で表示・再生・ミュートが共通になります。シーンごとに別のタイミングにしたい場合は、別ソースとして用意してください。

## Media Sourceの利用条件

Media Sourceのプロパティで、次の3項目を**OFF**にしてください。OBSの表示言語によって表記が異なる場合があります。

- 「繰り返し」（Loop / `looping`）
- 「ソースがアクティブになったときに再生を再開する」（Restart playback when source becomes active / `restart_on_activate`）
- 「非アクティブ時にファイルを閉じる」（Close file when inactive / `close_when_inactive`）

スクリプトがこの3項目を書き換えることはありません。条件が一致しない間は映像を非表示・消音にし、イベントを開始せず、フィルタの設定画面とスクリプトログに理由を表示します。条件を直すと初回表示の設定から動作を始めます。

本フィルタが再生を管理する間は、他の自動再生スクリプト、ホットキー、手動シーク等による再生操作を併用しないでください。メディアのファイルや再生速度の変更は、現在の再生時間を無効にするため初回動作からやり直します。

## 設定

| 項目 | 動作・既定値 |
|---|---|
| 間隔モード | 固定間隔（既定）／ランダム間隔 |
| 固定間隔 | 30秒 |
| ランダム最小・最大 | 20〜60秒 |
| 初回表示 | すぐに表示（既定）／最初の待機時間を経過してから表示 |
| 表示時間 | Persistent型のみ。5秒 |
| 表示時間の数え方 | 開始・終了エフェクトを含める（既定）／別に追加する |
| 開始エフェクト | なし／フェード／Peek／Wipe／Zoom（既定0.5秒） |
| 終了エフェクト | なし／フェード／Peek／Wipe／Zoom（既定0.5秒） |
| 開始／終了の変化のしかた | 一定（既定）／ゆっくり始まる／ゆっくり終わる／ゆっくり始まり、ゆっくり終わる。開始と終了は独立 |
| 開始Peek / Wipe方向 | ↑／↗／→（既定）／↘／↓／↙／←／↖／任意角度 |
| 終了Peek / Wipe方向 | ↑／↗／→／↘／↓／↙／←（既定）／↖／任意角度 |
| 開始／終了Wipe Softness | 0〜100%、1%刻み、既定0%。開始と終了は独立 |
| 開始／終了Zoom基準点 | 左上／上／右上／左／中央（既定）／右／左下／下／右下。開始と終了は独立 |
| 開始／終了Zoom倍率 | 50%（既定）。0〜1,000,000%の数値入力。開始と終了は独立 |

間隔は、**前回イベントが終了してから次回イベントが始まるまでの待機時間**です。10秒の動画と30秒の固定間隔なら、およそ10秒再生→30秒待機→次回再生となります。再生開始の準備にかかる時間は別に発生します。

ランダム間隔は待機に入った時に一度だけ抽選します。同じ待機時間が連続して選ばれる場合もあります。初回を待機にした場合は初回も抽選します。

秒数は小数2桁まで入力でき、刻みは0.01秒、上限は86,400秒です。表示時間は0.01秒以上、待機・エフェクトは0秒以上です。0秒の待機は空き時間なく次のイベントへ進む指定で、処理はフレーム単位になります。乱数範囲の最小値と最大値を逆に入力した場合は、小さい方から大きい方までとして扱います。

タイミングやエフェクトの変更は、実行中のイベント／待機を終えて次の段階へ進む際に反映します。有効・無効の切替は直ちに扱います。

### 表示時間の例

表示時間5秒、開始フェード0.5秒、終了フェード0.5秒の場合:

- **含める**: 0.5秒フェードイン → 4秒完全表示 → 0.5秒フェードアウト。合計5秒。
- **追加する**: 0.5秒フェードイン → 5秒完全表示 → 0.5秒フェードアウト。合計6秒。

含める方式でフェード時間の合計が表示時間を超えた場合は、開始・終了の比率を保って短縮し、完全表示の時間を0にします。例えば表示1秒に対して開始4秒・終了2秒なら、開始約0.667秒・終了約0.333秒になります。設定欄に入力した数値自体は書き換えません。

エフェクト「なし」、またはエフェクト時間0秒は即時切替です。終了エフェクトが「なし」でも、終了後は必ず完全非表示になります。「不透明度0%」が完全非表示、「不透明度100%」が入力本来の表示です。元画像の透明部分は維持されます。

「変化のしかた」は、Fade / Peek / Wipe / Zoomの0.0〜1.0の進行速度だけを変更します。「一定」はLinear、ほかの3種類はCubic Ease In / Ease Out / Ease In-Outです。エフェクトが「なし」の側には表示せず、保存済み設定に値がない場合も「一定」として従来どおり動作します。

PeekはScene Itemの位置・変形値やフィルタ出力サイズを変えず、元のソース領域内で映像内容だけを移動します。領域外は描画せず、色・明るさ・不透明度・元の透明／半透明部分は変更しません。矢印は映像が実際に移動する方向で、Peek InとPeek Outで意味は共通です。任意角度は0°=上、90°=右、180°=下、270°=左の時計回りで、1°刻みです。移動距離はソースサイズと方向から自動計算されます。

WipeはScene Itemの位置・変形値、フィルタ出力サイズ、映像内容の位置を変えず、元のソース領域内で直線境界だけを移動します。Softness 0%は従来どおりの硬い境界で、0%を超えると境界幅の中だけアルファが滑らかに変化します。境界幅は方向・角度を問わずソース高さを100%の基準とし、開始と終了で独立設定できます。色・明るさ・全体の不透明度・元の透明／半透明部分は変更しません。矢印はWipe In / Outのどちらでも境界が実際に進む方向です。任意角度はPeekと同じ定義です。

ZoomはScene Itemの位置・拡大率・回転などのTransform値を変えず、指定した9点の基準点を固定して映像だけを縦横同率で拡大・縮小します。開始は設定倍率から100%、終了は100%から設定倍率へ進みます。100%を超える部分は元のソース領域外にも描画し、100%未満の空き領域は透明です。色・明るさ・不透明度と元の透明／半透明部分は変更しません。0%は0倍行列を使わず、基準点上でサイズ0に見える完全透明出力として扱います。

Zoom倍率の1,000,000%はOBS標準数値入力に必要な実装上の最大値であり、正式な安全上限ではありません。極端な倍率の限界は未検証です。

## 動画の開始・終了

イベント開始時に標準Media Sourceへ先頭からの再スタートを要求します。終了済みの動画も次のイベントで再生します。APIの要求受付と、デコーダーが実際に再生を始めるタイミングは異なるため、再生を確認してから表示します。

動画長と現在位置を取得できる場合は、残り時間が終了エフェクト時間になったところから終了エフェクトを始めます。例えば10秒の動画に0.5秒の終了フェードまたはPeek Outなら、9.5秒付近から開始します。再生速度は実時間の秒数へ換算して扱います。短い動画では開始・終了エフェクトを比例縮小します。

動画長が不明なら終了エフェクトを省略し、実際の終了で即非表示にします。予想より早く終了した動画も即非表示にします。最終フレームを保持して終了後に追加エフェクトを行う機能はありません。

再生開始を10秒間確認できない、または再生位置が10秒間進まない場合は、停止・非表示・消音にして、通常の待機間隔後に再試行します。極端に遅いファイルや長時間同一フレームの素材では、この監視に抵触する場合があります。理由はOBSのスクリプトログで確認できます。

## シーン切替と非アクティブ

OBSの最終出力に対象ソースが参加している状態を「アクティブ」とします。配信・録画を開始している必要はありません。スタジオモードのプレビューだけにあるソースは、この意味でのアクティブには含めません。

非アクティブになった間は、待機時間・表示時間・フェード時間を止めます。Media型は動画本体も一時停止し、戻ったらその位置から再開します。Persistent型ではBrowserやGIF内部の時間は止まりません。

同じソースが別の出力中シーンに残っていれば、タイマーは進みます。シーントランジション中もOBSのactive判定に従います。ソースの表示チェックをOFFにして非アクティブになった場合も同じ扱いです。本フィルタ自身は表示チェックを操作しません。

## 音声と無効化

音声は今回の実装計画で追加された要件です。音量フェードは行わず、対象ソース単位のミュートを切り替えます。

- 完全非表示、開始準備、非アクティブ中は対象ソースをミュートします。
- 表示中は制御開始前のミュート状態に戻します。元からミュートなら無音のままです。
- 音量や音声モニタリング設定は変更しません。
- 同じソースの全参照先に作用します。制御中は、手動や別スクリプトによるミュート操作を併用しないでください。
- 消音対象は、そのソース自身がOBSへ出力する音声です。Browserからデスクトップへ出した音を別のデスクトップ音声ソースで拾う経路や、シーン・グループ内の子ソースをまとめて消音する処理は含みません。

フィルタの目のアイコンで無効化すると、映像効果を解除し、元のミュート状態へ戻します。Media型は途中停止なら再開し、停止・終了済みなら先頭から再生します。表示できない状態では、次に表示可能になった時に一度だけ再生します。フィルタ単独の削除も同様です。

再有効化、OBS再起動、スクリプト再読み込みでは初回表示の設定から始まります。途中の残り時間は保存しません。OBS終了・親ソース破棄時に新しい動画再生は要求しません。

## 制約

- 映像切替はフレーム単位です。動画の読み込み・デコードや音声バッファによる遅延があり、音声サンプル単位の厳密な同期は保証しません。
- 透明になってもBrowserやCaptureの処理負荷は止まりません。Media Sourceのファイルを閉じない設定はメモリを使用します。
- 初版はSDRが対象です。HDRの色保持、Windows/Linuxでの動作は未検証です。
- 別のフィルタが後段で不透明な映像を生成する構成では、本フィルタより後に映像が現れる場合があります。本フィルタが最終的な表示を制御する順序にしてください。
- 通常の無効化・削除では復元しますが、OBSの強制終了やスクリプトファイルの欠落時まで自動復元を保証しません。必要ならOBS音声ミキサーで対象ソースのミュートを解除してください。
- スクリプトそのものを削除した後には、将来のアクティブ化を監視するコードは残りません。表示していないMedia Sourceをその後再生するには、OBS側から再生を操作してください。

## 初版に含まない機能

Slide、Pop、Rotate、Pulse、Softness以外のFeather形状、Gaussian Blur、Cubic以外のイージング曲線、Zoom倍率スライダー、任意Zoom基準点、縦横比を維持しないZoom、複数エフェクトの組合せ、外部フィルター連携、非アクティブ中のタイマー継続、ランダム表示時間、確率・回数条件、初回専用間隔、Image Source GIFの先頭復帰、テスト再生ボタン、残り時間表示は実装していません。

## 開発用検証

`tests/run_guarded.py`経由で`tests/run_obs.py`を起動します。実行ごとにC製の終了ガードを用意し、クラッシュ・タイムアウト・終了処理の失敗を合格に見せず、`verification/`へログを保存します。インストール済みOBS 32.0.4のライブラリを使う独立プロセスで、利用者のOBS設定・シーンコレクションは読み込みません。GPU試験には通常の画面アクセスが必要です。

ガード自己試験はOBS受入試験とは別に、クラッシュ3種とタイムアウトを確認します。OBSを読み込まない終了条件だけの検査は次のコマンドです。

```sh
/opt/homebrew/bin/python3.11 tests/test_shutdown.py
```

ガード自己試験と独立OBS試験は、次のように実行します。自己試験のPASSはOBS受入の合格を意味しません。

```sh
/opt/homebrew/bin/python3.11 tests/run_guarded.py --self-test --signal SIGSEGV
/opt/homebrew/bin/python3.11 tests/run_guarded.py --self-test --signal SIGBUS
/opt/homebrew/bin/python3.11 tests/run_guarded.py --self-test --signal SIGABRT
/opt/homebrew/bin/python3.11 tests/run_guarded.py --self-test
/opt/homebrew/bin/python3.11 tests/run_guarded.py tests/integration.lua --graphics --modules --audio --seconds 60
```

時間計算の合格は、実際のGPU描画や音声の合格とは区別します。再現可能な試験範囲と未確認事項を受入試験記録へ残します。

統合試験では個別検査後にソースを解放し、残存ソース0件とLua終了処理の成功を確認してからOBSライブラリを終了します。個別検査の`test-result.txt`だけでは合格になりません。`process-result.txt`の成功記録とプロセス終了コード0の両方が必要です。終了前提の失敗による終了コード2は不合格です。
